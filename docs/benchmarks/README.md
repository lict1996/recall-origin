# RecallOrigin offline benchmark

This benchmark is an evidence generator, not a leaderboard claim. It runs without network
access and records raw observations alongside aggregate metrics.

## What it measures

- Deterministic synthetic corpus with exact and lexical relevance labels.
- Behavioral cases for exact/lexical retrieval, valid time plus transaction time, exact
  partition isolation, and deletion non-resurrection after purge, reindex, and reopen.
- Recall@k, MRR, search p50/p95/p99, end-to-end `MemoryEngine.remember` throughput, and
  aggregate SQLite storage size.
- Per-query-type retrieval and latency metrics, so exact and lexical results remain
  distinguishable rather than being hidden behind one aggregate.

No vector retriever is configured by this benchmark. The artifact records the vector
baseline as unmeasured and never substitutes an estimate.

## Reproduce

From the repository root:

```bash
uv run python -m recall_origin.benchmarks.runner \
  --scale 100 \
  --seed 20260830 \
  --query-count 25 \
  --output /tmp/recall-origin-smoke.json \
  --inspector-output /tmp/recall-origin-inspector.json
```

The default `100` scale is a fast smoke check. Supported measurement scales are `10000`,
`100000`, and `1000000`. All writes use the public `MemoryEngine.remember` API, one
transaction per memory. Large scales are therefore intentionally real end-to-end ingest
runs and can take substantial time and disk space.

`--relaxed-durability` is available for local profiling, but its artifact explicitly records
`durable: false`. Do not compare it with a durable run as if the configurations matched.

## Generate official 10k release evidence

The checked-in 10k evidence set must be generated from an existing clean commit:

```bash
test -z "$(git status --porcelain=v1 --untracked-files=all)"
uv run python scripts/benchmark_release.py
```

This wrapper is intentionally narrower than the general benchmark runner. It fixes the
release configuration at 10,000 documents, seed `20260830`, 250 queries, `k=10`, and
durable SQLite. It runs the measurement in a staging directory, requires the same clean
Git commit before and after the run, verifies that the Inspector projection exactly matches
the canonical artifact, generates the summary/CSV/SVG and checksums, and publishes
`SHA256SUMS` last. A failed measurement or validation therefore cannot produce a
checksum-valid release bundle.

`scale-10000-durable-run.json` is generated by the same wrapper. It records the portable
wrapper and runner commands, UTC and local start/end times, wall/user/system time, the
canonical artifact SHA-256, Git commit, uv version, Python runtime, and `uv.lock` SHA-256.
Do not hand-edit or reuse run metadata from an earlier measurement.

After generating a bundle, verify it before updating release copy:

```bash
(cd docs/benchmarks/results && shasum -a 256 -c SHA256SUMS)
uv run pytest -q tests/benchmarks
```

The release evidence test requires the artifact's Git commit to be available, clean at
measurement time, and an ancestor of the checked-out release commit. This supports a
two-commit evidence workflow: measure from clean commit A, then commit only the resulting
evidence and synchronized documentation as commit B.

## Artifact interpretation

The top-level JSON contains:

- `schema_version`, `generated_at_utc`, git/Python/platform provenance;
- complete engine and experiment configuration;
- canonical corpus SHA-256;
- every behavioral case's expected and actual results;
- every retrieval query's labels, returned ranks, component scores, and duration;
- aggregate retrieval/performance metrics and database file-size breakdown;
- `inspector_payload`, derived only from values measured in that same artifact.

Latency and throughput naturally vary by hardware and load. Corpus content, query labels,
and corpus hash are deterministic for a given `(scale, seed)`. Query targets use a
documented, hash-seeded coprime cycle rather than Python's runtime RNG implementation.
The artifact also records a content fingerprint of the package sources and dependency
metadata, and the runner refuses to emit evidence if that fingerprint changes during a run.
